# 三只叠

Status: ready-for-agent

## Problem Statement

我想做一款能发给朋友的麻将消除小游戏。朋友用手机打开链接就能玩：有多关、有分数、失败可以重来，微信内置浏览器也要能撑住。规则要一眼能懂，牌面要认得出来，同一关大家打的是同一局，这样才能比星、比分。

## Solution

做一款名叫 **三只叠** 的竖屏网页游戏。场上是一堆散落叠放的麻将牌，只能点完全露出的牌；点中的牌进入底部 7 格槽，槽里任意位置凑齐三张相同即消除。槽满失败，场上和槽都清空则过关。一共 12 关、固定种子、条筒万牌面（每种恰好三张），带星和总分、关卡选择、有限撤回/洗牌、本地存档。用 Vite + TypeScript 做成静态页，托管到 GitHub Pages。

## User Stories

1. As a 收到链接的朋友, I want 用手机浏览器打开就能玩, so that 不用安装、不用注册。
2. As a 微信用户, I want 在微信内置浏览器里完整可玩, so that 聊天里点开链接即可开始。
3. As a 玩家, I want 看到标题「三只叠」, so that 我知道这是什么游戏。
4. As a 玩家, I want 竖屏布局（上方牌堆、底部槽、顶栏状态）, so that 单手点选时槽和牌都够得到。
5. As a 首次进入第 1 关的玩家, I want 看到三句可关掉的说明（只能点完全露出的牌；槽里三张相同会消；槽满失败）, so that 我不用猜规则。
6. As a 已经看过说明的玩家, I want 再次进入第 1 关时不再弹出说明, so that 重玩不被挡住。
7. As a 玩家, I want 关掉说明后立刻能点牌, so that 教学不变成强制演示关。
8. As a 玩家, I want 看到扁平传统条筒万牌面, so that 我能靠花色和点数认牌。
9. As a 第 1 关玩家, I want 场上只有一筒到六筒共 18 张, so that 开局只认一种花色和六个点数。
10. As a 玩家, I want 牌堆居中散落并带一点旋转, so that 看起来是一堆叠着的牌，而不是表格。
11. As a 玩家, I want 牌落在顶栏和底槽之间的安全区, so that 点牌时不会和按钮抢位置。
12. As a 玩家, I want 只有完全露出的牌能被点进槽, so that 遮挡成为解谜的一部分。
13. As a 玩家, I want 被更高一层牌矩形相交盖住的牌点不动, so that 「完全露出」的判定稳定、能讲清。
14. As a 玩家, I want 点一张被盖住的牌时得到拒绝反馈, so that 我知道这张现在不能拿。
15. As a 玩家, I want 点一张可点的牌后它从场上进入槽, so that 我能看到自己的选择。
16. As a 玩家, I want 槽里任意位置凑齐三张相同就立刻消除, so that 我不必把相同的牌挨着放。
17. As a 玩家, I want 进槽那张若凑成三只则先消再判断槽是否满, so that 第 7 张凑消时算过而不是失败。
18. As a 玩家, I want 槽里最多 7 张, so that 我必须规划顺序，不能无限制囤牌。
19. As a 玩家, I want 消完后槽仍为 7 张时判定失败, so that 胜负明确。
20. As a 玩家, I want 场上和槽都清空时判定过关, so that 清盘就是胜利。
21. As a 失败的玩家, I want 立刻重开本关, so that 我可以再试同一局。
22. As a 失败的玩家, I want 重开后仍是这一关的同一副固定牌局, so that 我是在学这关，而不是换题。
23. As a 玩家, I want 每关有 3 次撤回, so that 点错可以退回。
24. As a 玩家, I want 撤回回退上一手，并恢复那一手触发的三消, so that 撤回是完整的状态回放。
25. As a 玩家, I want 没有可撤回的手时撤回不可用, so that 我不会按空按钮。
26. As a 玩家, I want 每关有 1 次洗牌, so that 场上卡住时还有一次重组机会。
27. As a 玩家, I want 洗牌只重排场上剩余牌、槽里的牌不动, so that 我已经进槽的选择还在。
28. As a 玩家, I want 洗牌后这一关仍然有解（计入当前槽）, so that 唯一一次洗牌不会洗成死局。
29. As a 玩家, I want 场上没有剩余牌时洗牌不可用, so that 空操作不会出现。
30. As a 玩家, I want 用掉的撤回和洗牌次数在本关内减少, so that 我能看到还剩几次。
31. As a 玩家, I want 失败或重开后本关的撤回 3、洗牌 1 恢复满, so that 每一局都有完整道具。
32. As a 玩家, I want 开局这一关保证有解, so that 朋友不会碰到「这关根本过不了」。
33. As a 玩家, I want 所有人的同一关是同一副牌（固定种子）, so that 我们可以比较星和分。
34. As a 过关玩家, I want 得到 1 到 3 星, so that 我知道这关过得干不干净。
35. As a 过关且没用撤回也没用洗牌的玩家, I want 得到 3 星, so that 完美通关有区别。
36. As a 过关且用了撤回但没用洗牌的玩家, I want 得到 2 星, so that 靠撤回过关和完美通关能分开。
37. As a 过关且用了洗牌的玩家, I want 得到 1 星, so that 用了最后手段仍然算过关。
38. As a 过关玩家, I want 看到本关分数：每次三消 +100、每剩 1 次撤回 +50、未用洗牌 +200, so that 我知道分从哪来。
39. As a 玩家, I want 在关卡选择页看到每一关的解锁状态和最好星级, so that 我知道自己打到哪、哪关还能刷。
40. As a 新玩家, I want 第 1 关默认解锁、后面按序解锁, so that 进度是一条线。
41. As a 刚过关的玩家, I want 下一关被解锁, so that 我可以继续往下打。
42. As a 过关玩家, I want 弹窗上选择「下一关」或「返回选关」, so that 连打和回去看进度都可以。
43. As a 已过关玩家, I want 重玩已解锁的关并刷新该关最好星和最好分, so that 我可以刷成绩。
44. As a 重玩未超过原成绩的玩家, I want 该关最好星和最好分保持原值, so that 一次更差的重玩不会把记录打坏。
45. As a 玩家, I want 总分等于各关最好分之和, so that 有一个可以炫耀的数字。
46. As a 打完第 12 关的玩家, I want 看到结束页, so that 我知道这就是完整游戏。
47. As a 通关玩家, I want 从结束页回到关卡选择, so that 我可以回头刷星。
48. As a 回访玩家, I want 关掉页面再打开后仍保留关卡解锁、最好星、最好分和静音偏好, so that 我不用从头打。
49. As a 回访玩家, I want 从关卡选择页接着玩, so that 本地存档直接反映在选关上。
50. As a 玩家, I want 第一次点屏幕后才出现音效, so that 微信里音频能播出来。
51. As a 玩家, I want 点击、消除、失败有音效, so that 操作有反馈。
52. As a 玩家, I want 能静音, so that 在安静场合也能玩。
53. As a 玩家, I want 无背景音乐, so that 不必处理循环音乐和额外版权。
54. As a 第 2 关玩家, I want 场上多出七筒（7 种、21 张）, so that 难度从第 1 关只加一种。
55. As a 第 4 关玩家, I want 筒 1–9 全部出现（9 种、27 张）, so that 单色筒打满。
56. As a 第 5 关玩家, I want 开始出现条, so that 花色从一种变成两种。
57. As a 第 12 关玩家, I want 18 种 54 张、深叠的牌堆, so that 最后一关明显更难。
58. As a 玩家, I want 第 1 关开局至少 4 张可点, so that 开局不会无牌可点。
59. As a 玩家, I want 后面关开局至少有可点的牌, so that 倒序铺牌的结果能上手就玩。
60. As a 玩家, I want 每种牌在一关里恰好 3 张, so that 清盘在数学上成立。
61. As a 玩家, I want 这 12 关里不出现万, so that 种类数停在 9 筒 + 9 条。
62. As a 玩家, I want 顶栏看到当前关卡、剩余撤回、剩余洗牌, so that 决策时不必记数字。
63. As a 玩家, I want 槽在视觉上就是 7 个格子, so that 我能预判还剩几格。
64. As a 失败玩家, I want 看到失败反馈后再选重开或返回选关, so that 失败不是闪一下就没了。
65. As a 玩家, I want 撤回和洗牌是免费且每关定量的, so that 发给朋友的版本没有体力墙。
66. As a 玩家, I want 不限重开次数, so that 我可以一直试到过关。
67. As a 作者, I want 公开仓库加 GitHub Pages 得到一个 URL, so that 我能把链接发给朋友。
68. As a 作者, I want 无后端、无账号, so that 第一版静态托管就能交货。
69. As a 玩家, I want 文案是中文, so that 规则说明和按钮都读得懂。
70. As a 玩家, I want 在 Safari 和 Chrome 里同样能玩, so that 不只依赖微信。
71. As a 玩家, I want 牌面是自己绘制的 SVG 而不是系统麻将字符, so that 微信和 iOS/Android 上看起来一样。
72. As a 玩家, I want 点到可点牌时有点击音效（未静音时）, so that 选牌有确认感。
73. As a 玩家, I want 三消时有消除音效（未静音时）, so that 成功匹配有奖励感。
74. As a 玩家, I want 槽满失败时有失败音效（未静音时）, so that 结束状态听得出来。
75. As a 静音玩家, I want 所有音效都不出声, so that 静音是彻底的。
76. As a 玩家, I want 从选关页进入某一已解锁关时道具是满的, so that 每一局独立。
77. As a 玩家, I want 对局中途返回选关时本局进度不必写进最好成绩, so that 没打完的一局不会当作成绩。
78. As a 玩家, I want 计时器不存在, so that 我可以慢慢想。
79. As a 视力普通的手机玩家, I want 牌面纹样大、触控面积大, so that 在微信小屏上能点准。
80. As a 玩家, I want 过关弹窗上看到本关星和分, so that 我马上知道这局的评价。

## Implementation Decisions

- 产品名：三只叠。浏览器标题、结束页、选关页都用这个名字。文案语言：中文。
- 形态：静态网页，手机竖屏优先；微信内置浏览器必须可玩。不做微信小游戏、无后端、无账号。
- 技术：Vite + TypeScript；牌面为 DOM/SVG；无 React/Vue、无 Canvas 游戏引擎。交付为 GitHub Pages URL，仓库公开。
- 模块划分（按职责，不按文件）：
  - **对局（唯一测试缝）**：一关从开局到胜负的全部规则。对外是「用关卡号开局」或「用一副已知牌局开局」，以及指令：点牌、撤回、洗牌、重开。对外只提供快照：场上每张牌的标识、牌面、矩形、层、是否可点；槽内牌面列表；剩余撤回/洗牌；状态（进行中 / 过关 / 失败）；过关时的星和本关分。
  - **关卡目录**：12 关的固定种子、种类列表、张数、深浅叠参数。对局开局时向目录取一关配置并倒序铺牌。
  - **界面**：选关、对局台面、教学叠加层、过关/失败/结束弹窗、静音。只发送指令、渲染快照，不实现规则。
  - **本地存档**：关卡解锁、每关最好星、每关最好分、是否已看过第 1 关教学、静音。微信清缓存丢失，接受。
  - **音效**：点击 / 消除 / 失败三声；第一次指针或触摸之后才解锁播放；无 BGM。
- 对局规则：
  - 槽容量 7。槽内任意位置三张相同即消，不必相邻。
  - 点入槽时：先把该牌放入，再消除所有已凑齐的三只，再判断是否满 7 张。满则失败。
  - 场上与槽都为空则过关。
  - 「可点」：不存在更高一层且轴对齐矩形与本牌相交的牌。相交即盖住。
  - 撤回：最多 3 次，回退上一手完整快照（含该手引发的三消）。
  - 洗牌：最多 1 次，只重排场上剩余牌；必须在计入当前槽的前提下仍保证可清盘。
  - 重开：同一关同一种子重新铺牌，道具回满。未过关离开不写最好成绩。
- 铺牌：按一个合法通关顺序倒着盖上去，开局保证有解。第 1 关开局至少 4 张可点；其余关开局至少 1 张可点。牌堆为一块居中散落堆，轻微旋转，限制在顶栏与槽之间。
- 牌面与关卡表：扁平传统条筒万纹样；每关每种恰好 3 张。种类按筒→条增加。万不出现。

| 关 | 种类数 | 张数 | 牌面 |
|---|---|---|---|
| 1 | 6 | 18 | 一筒–六筒 |
| 2 | 7 | 21 | 加七筒 |
| 3 | 8 | 24 | 加八筒 |
| 4 | 9 | 27 | 加九筒 |
| 5 | 10 | 30 | 加一条 |
| 6 | 11 | 33 | 加二条 |
| 7 | 12 | 36 | 加三条 |
| 8 | 13 | 39 | 加四条 |
| 9 | 14 | 42 | 加五条 |
| 10 | 15 | 45 | 加六条 |
| 11 | 16 | 48 | 加七条 |
| 12 | 18 | 54 | 加八条、九条 |

- 第 1 关浅叠，第 12 关深叠，中间关叠层随关卡加深。
- 星：3 星 = 本局撤回与洗牌都未使用；2 星 = 使用过撤回、未使用洗牌；1 星 = 使用过洗牌。过关至少 1 星。
- 本关分：每次三消 +100，过关时每剩余 1 次撤回 +50，过关时未用洗牌 +200。12 关每种最多 6 次三消（18 种 × 3 张 / 3），分数按实际三消次数计。
- 选关：按序解锁；第 1 关默认解锁。可重玩已解锁关。每关保留最好星、最好分。总分 = 各关最好分之和。过关弹窗提供下一关与返回选关。第 12 关过关后进结束页，可回选关。
- 教学：仅第一次进入第 1 关时出现三句可关叠加层；关掉后用存档记住，不再出现。
- 存档键位与界面路由由实现自定；行为必须满足上述读写语义。

## Testing Decisions

- 好测试只通过对外接口观察行为：给指令、读快照。不断言铺牌算法的内部顺序、DOM 结构、SVG 路径、localStorage 键名。期望值来自本规格中的数字和规则（7 格、3 张成组、星级表、分值、关卡张数），不从实现里抄一遍再断言。
- **测试缝只有一处：对局。** 界面、存档、音效、GitHub Pages 不作为本规格的自动化测试缝。对局模块的接口同时服务界面和测试。
- 在该缝上覆盖的外部行为：
  - 第 1 / 4 / 5 / 12 关开局：种类数、张数、每种 3 张、开局可点数、有解（存在一条清盘指令序列）。
  - 盖住的牌不能进槽；露出的牌可以。
  - 槽内任意位置三只即消；第 7 张凑消后不过失败。
  - 消完后仍 7 张则失败；清盘则过关并给出符合规则的星和分。
  - 撤回恢复上一手（含三消回滚），次数上限 3。
  - 洗牌不改槽，洗完仍有解，次数上限 1。
  - 重开回到该关固定种子，道具回满。
- 仓库里目前没有测试，无 prior art。新测试只打在对局缝上。
- 微信 WebView、触控、音效解锁、存档在清缓存后丢失，用手工验收，不写入对局缝测试。

## Out of Scope

- 万牌、风牌、箭牌、花牌
- 计时、限时失败、体力/爱心
- 背景音乐、震动、付费道具、广告、账号、排行榜、联网对战
- 微信小游戏、App Store、桌面优先布局、横屏专版
- 关卡编辑器、30 关以上、手写几何台面
- React/Vue、Phaser/Pixi 等引擎、服务端
- 相邻才消除的槽规则、多列牌堆、上海麻将式自由端
- 云存档；微信清缓存后的进度恢复保证

## Further Notes

- 第 12 关正好用完九筒与九条（18 种）。万在本规格的 12 关内不出现，这是种类数 6→18 且按筒→条加号的推论，不是疏漏。
- 固定种子用于「所有人同一关同一局」。种子的具体整数可在实现时选定，一经发布不要改，否则朋友之间的星和分不再可比。
- 微信内置浏览器：音频必须在一次用户手势后播放；视口需避开顶栏/底槽和浏览器铬；以真机微信点开 Pages URL 为手工验收标准。
- 本仓库尚未配置工程技能用的 issue tracker。若要把本规格登记为带 `ready-for-agent` 的工单，先跑 `/setup-matt-pocock-skills`。
